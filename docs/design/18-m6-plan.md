## 1. 现状（10-31）

已有：
- 三端安装包在本机出齐，有虚拟机验证脚本（13第2节）。
- 应用包热更新：签名清单、全文件校验、槽位、坏包自动回滚、修复模式。
- 更新源`feed-<channel>.json`，带吊销列表。
- 发布签名的接口：设了`XORA_SIGNING_KEY_FILE`就用发布私钥签名；`XORA_RELEASE=1`时，安装包只信任`build/keys/trusted/*.pub`里的公钥。

- shell整包更新。
- 预设数据（模型目录、价格、怪癖）在线更新：现在写在代码里，只能随应用包更新。
- 外部引擎的版本管理：现在用`npx -y`现拉最新版，没锁版本，也没校验。
- 安装器里的修复模式入口。
- 发布脚本。
- 1.0的用户文档和官网：`website/`还是0.2.6的站（xora-code.com，自建服务器），`docs/guide`只有工作流一篇。

## 2. 相对设计稿的调整

| 项 | 设计稿 | 调整为 | 理由 |
|---|---|---|---|
| 签名密钥 | 主私钥离线保存，ci用受限的子密钥签名 | 先用一把发布密钥，离线保存；信任列表可以放多把，用来轮换。子密钥等以后ci出包时再加 | 出包和签名都在本机做（10-31用户定），没有ci签名的需要 |
| 更新源 | 只签清单 | 更新源也签名。客户端验签通过后，才认其中的吊销、灰度和最低版本 | 不签的话，改一下更新源就能让客户端回滚或拒绝更新 |
| shell整包更新 | electron-updater | 自己做最小的一套：host下载，shell验签后执行。windows静默运行nsis安装器再重启，linux的AppImage原地替换，deb和mac提示下载 | bootstrap要保持小；签名沿用应用包的ed25519，不依赖代码签名证书。mac没有证书，electron-updater本来也用不了 |
| 差分更新 | windows用blockmap差分 | 1.0先全量下载（约110mb） | 先把流程走通，差分以后再加 |
| 外部引擎 | 引擎安装器：校验、原子切换、失败退回 | 1.0先锁版本：注册表写死版本号，用`npx -y 包名@版本`。安装器放到1.0之后 | 先堵住“每次启动拉最新版”的风险，工作量小 |
| 国内镜像 | github releases加国内镜像，客户端自动选源 | 客户端支持配多个更新源，依次尝试并记住能用的那个。镜像的存储和上传，等用户定用哪家 | 需要用户自己的对象存储账号 |
| 灰度 | 按安装id的哈希分桶 | 同。安装id只在本机用来算桶，不上传 | 本地优先，不收集数据 |

## 4. 需要用户定

1. 发布私钥放在哪。建议放密码管理器，另留一份离线备份；不进仓库，本机也不留明文。

3. 官网是在现在的next站上改内容，还是换成静态站。部署仍在用户的服务器上。
4. 外部引擎在1.0只锁版本，安装器放到1.0之后，是否可以。
5. 公测的版本号（比如1.0.0-beta.1）和发布时间。
