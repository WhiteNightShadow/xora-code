# 11｜用量与成本（用户侧花费核算）

## 1. 范围

- 这里的"计费"指用户自己的花费核算，包括各家厂商的按量费用、订阅额度的消耗和预算控制。xora本身不收费，不做账户和支付。
- 目标：在任何一级都能回答三个问题：花了多少、花在哪里、还剩多少。

## 2. 计量层级

```
单次请求 → 轮 → 线程（含子agent） → 任务 → 工作流运行 → agent → 项目 → 全局
横向维度：厂商 · 通道（api / 订阅key / 官方agent / 本地） · 模型 · 场景模板 · 时间（日、周、月）
```

每一级都能单独查看、单独设预算。

## 3. 用量事件

每次模型请求结束时，host写一条用量事件，存进sqlite，按线程、agent和日期建索引。

| 字段 | 说明 |
|---|---|
| `id`、`ts` | 唯一id、时间 |
| `projectId`、`threadId`、`turnId`、`agentPath` | 归属；`agentPath`区分主线程和子agent，比如`main/sub-2` |
| `agentId`、`taskId`、`workflowRunId` | 常驻agent、任务、工作流运行（见06） |
| `role`、`tier` | 角色（主管、执行者、审查等）和档位（旗舰、标准、经济、快速），用来统计按档位的花费和监督开销 |
| `template`、`engine` | 场景模板；xora engine或外部agent名 |
| `provider`、`channel`、`region`、`model` | 厂商、通道、区域、模型 |
| `inputTokens`、`cachedTokens`、`cacheWriteTokens`、`outputTokens`、`reasoningTokens` | token明细 |
| `requests`、`serverToolCalls` | 请求数，以及厂商侧计费的工具调用（如search、fetch） |
| `latencyMs`、`ttftMs` | 总耗时、首字耗时 |
| `cost` | 估算金额、币种、价格表版本、计价时段（高峰或空闲）、命中的价格档 |
| `quota` | 订阅额度的消耗：单位、数量、所属窗口 |
| `status`、`errorClass` | 成功或失败，以及错误类别 |
| `source` | 数据来源：厂商返回、本地估算、acp `usage_update` |

## 4. 计价：厂商的阶梯价和时段规则

价格表是预设数据（见07），每条都有版本号。字段包括：

- **基础单价**：输入（缓存命中、未命中）、输出；推理token单独计价时也列出。
- **缓存写入**：比如kimi的5分钟和1小时两档。
- **上下文长度分档**：部分厂商在上下文超过某个长度后，单价会上调。
- **时段规则**：比如deepseek工作日9–12点、14–18点为高峰，其余时间（含周末和法定节假日）半价。
- **服务端工具**：比如deepseek的search、fetch，从2026-11-01起每千次5元。
- **币种**：人民币或美元。用户可以设汇率，用来汇总合计。
- **本地模型**：默认按0计，也可以填一个机时单价。

每条用量事件都记录价格表版本和命中的价格档。价格调整后，历史费用可以重新计算。

## 5. 订阅额度

- **档位和窗口进预设**：
  - glm coding plan分lite、pro、max三档，各有5小时积分和周积分（调研所得，未复核）。
  - kimi code是5小时窗口加月总量，各档的具体数字官方没有公开。
- **消耗估算**：
  - glm按积分公式计算。以下来自调研，未复核：glm-5.3每次消耗的积分=(输入×6.9+命中×1.7+输出×24)÷10000，工作日14–18点全价，其余时段减半。
  - kimi code只能从429响应和返回信息里推断。
  - 官方agent的订阅由官方客户端管理，界面上显示"不可见"。
- **窗口状态**：显示已用和剩余（估算）以及下次重置时间。
  - 接近上限时提醒。
  - 用尽时可以选择自动切到备用通道，比如改走按量api。

## 6. 展示

| 位置 | 内容 |
|---|---|
| 线程顶栏 | 本线程花费、上下文占用 |
| 轨迹视图 | 每一步的token和费用 |
| agent名册 | 每个agent的今日花费、本月花费 |
| 工作流运行 | 每次运行的总花费和每一步的花费 |
| 团队视图 | 按档位、按agent的花费；监督开销占比（主管花费占总花费的比例）；各档位的一次通过率 |
| 用量面板 | 今日、本周、本月；按厂商、通道、模型、项目、agent、模板、工作流拆分；缓存命中率；高峰与空闲的占比；订阅额度 |

数据可以导出csv。以后支持导入厂商账单做对账。

## 7. 预算与省钱

- **层级预算**：全局、项目、agent、工作流（每次运行）、线程、单轮，都可以设日上限和月上限。
- **超支动作**：到80%提醒；到100%暂停并询问，也可以设成硬停止。
- **峰谷调度**：定时任务和工作流可以设成只在空闲时段运行（见06）。
- **省钱提示**：出现以下情况时给出具体建议：
  - 缓存命中率低：比如提示"会话中途改了思考强度"。
  - 长上下文占比高：建议压缩，或者把探索交给子agent。
  - 高峰时段用量占比高：比如提示"这个定时任务改到空闲时段，可以省一半"。

## 8. 数据与隐私

- 用量数据只存在本机sqlite里，不上传。
- 用量事件里只记计量字段，不记提示词内容（提示词本身在线程日志里）。
