6. **有意移植的旧资产**（按思路重写，不复制代码）：
   - fake acp agent的测试思路
   - 官方npm更新链的校验流程（改成通用的引擎安装器）

## 3. 风险

| 风险 | 对策 |
|---|---|
| bootstrap一旦发布就很难修 | 保持极小（2000行以内），测试覆盖全部分支；真要修只能靠shell整包更新 |
| 自研引擎的质量：编辑可靠性、压缩策略、长任务 | 建评测集；保留外部引擎做a/b对照 |
| pi上游每周发版，出过不兼容改动 | 锁版本，中间加适配层 |
| 国产厂商端点和模型变动频繁（kimi k2下线、deepseek模型改名） | 预设数据在线更新，启动时核对`/models` |
| 订阅条款 | 见07第10节；不伪造客户端标识，订阅通道不做无人值守批跑 |
| 多agent错误级联、成本失控 | 每个任务都要验收或人工确认；每个agent和每次运行都有预算；高风险动作走关卡 |
| 主管拆分的质量不稳定、监督开销过高 | 跨家族的计划评审；任务卡必须带验收标准；显示监督开销占比；用评测集比较不同的档位组合 |
| windows沙箱不成熟 | 先用审批加路径边界兜底 |
| 热更新包被篡改 | 清单签名，启动时校验哈希；私钥离线保存 |
| electron升级节奏（每8周一个大版本，只支持最近3个） | 每季度升级一次，ci里跑原生模块测试 |
| 没有签名证书，mac上shell无法自动更新，windows有smartscreen拦截 | 应用包热更新照常工作；文档写清安装方法；证书最后再考虑 |
| 重写期间没有新版可用 | 旧版0.2.x继续可用，直到1.0公测 |
