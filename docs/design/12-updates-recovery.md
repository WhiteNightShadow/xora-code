# 12｜更新、版本管理与修复

## 1. 目标

- 更新不打断进行中的任务；更新失败不损坏现有安装和数据。
- 任何一次更新都能退回上一版。应用连续启动失败时自动回滚；最坏情况下进入修复模式。
- 未签名的mac包也能拿到代码更新：应用包热更新用xora自己的签名，不依赖系统签名。

## 2. 版本体系

| 组件 | 内容 | 更新方式 | 版本示例 |
|---|---|---|---|
| shell | electron、bootstrap、preload、原生模块、安装器 | 整包更新（electron-updater；mac要求签名） | 1.2.0 |
| 应用包 | ui、host、xora engine的js | 热更新，切换槽位 | 1.2.7 |
| 外部引擎 | codex、claude、opencode、grok等 | 引擎安装器（见05） | 各自的版本 |
| 预设数据 | 模型目录、价格、怪癖、内置场景与skills | 签名数据包，热加载 | 2026.10.29.1 |
| 扩展 | 插件、skills、mcp | 市场（见09） | 各自的版本 |
| 数据格式 | sqlite schema、事件日志格式 | 随应用包迁移 | schema 7、events v1 |

兼容矩阵写在每个应用包的签名清单里：

```json
{
  "version": "1.2.7",
  "channel": "stable",
  "requires": {
    "shell": ">=1.2.0 <2.0.0",
    "electronAbi": "<abi>",
    "schema": { "reads": [6, 7], "writes": 7 }
  },
  "files": [{ "path": "host/index.js", "sha256": "…", "size": 123456 }],
  "rollout": { "percent": 20 },
  "signature": "ed25519:…"
}
```

- **渠道**：stable、beta、nightly，用户可以切换。从高渠道切回低渠道时，提示是否降级。
- **版本号**：semver。shell和应用包各自独立编号；对外的"xora版本"以应用包版本为准。

## 3. 应用包热更新

- **槽位**：
  - 每个版本一个目录`app/slots/<version>/`。
  - `app/state.json`记录`current`、`previous`、`lastGood`、`pending`和启动尝试次数。不用符号链接，兼容windows。
- **内置基线**：安装包里自带一份应用包（factory），永远可用。
- **流程**：
  1. 检查清单并验签。
  2. 下载，支持断点续传；差分包以后再做。
  3. 逐个文件校验。
  4. 写入新槽位，标记为`pending`。
  5. 空闲时提示重启，或者等下次启动生效。任务运行中不切换。
- **保留**：当前版、上一版和基线；其他旧槽位按磁盘空间清理。
- **启动校验**：bootstrap启动时先校验清单签名和文件哈希。校验失败的槽位不加载，直接按第4节回退。

## 4. 启动健康检查与自动回滚

```
启动 → bootstrap读state.json
  ├─ 有pending：尝试pending（启动尝试次数+1）
  └─ 没有：用current
加载应用包 → 等待三个条件：host就绪、ui首屏渲染完成、稳定运行20秒
  └─ 都满足 → 标记good（lastGood=当前版本，尝试次数清零）

异常判定（下次启动时检查）：
  - 同一版本连续2次没达到good（崩溃、卡死、被强制退出）
      → 标记bad，切到lastGood，提示"已自动回滚到x.y.z"
  - lastGood也连续失败 → 切到内置基线
  - 基线也失败 → 进入修复模式

看门狗：30秒内ui没有就绪 → 弹出"启动缓慢"对话框：继续等待 / 进入修复模式 / 回滚
```

- **host运行中崩溃**：bootstrap自动重启host，5分钟内最多3次；超过就提示进入修复模式。
- **吊销**：服务端清单把某个版本标为吊销后，客户端下次启动直接回滚到`lastGood`，并说明原因。

## 5. 修复模式

**进入方式：**

1. 自动：连续启动失败（见第4节）。
2. 菜单：应用菜单"帮助→重启到修复模式"；mac程序坞右键菜单里也有同名项（M0已实现）。
3. 命令行：`--safe-mode`或`--repair`（M0已实现）。
4. 安装器创建的入口：windows开始菜单里的"xora code（修复模式）"（M6做）。

原计划里的"启动时按住shift或option"没有做：electron没有在启动时读取按键状态的接口，只能靠原生模块，和"少原生依赖"的原则冲突。

**界面**：bootstrap内置的静态页面，不依赖应用包，不加载任何扩展。

**功能：**

- **版本**：查看当前版、上一版、基线，一键回滚应用包；回滚引擎；切换渠道。
- **扩展**：一键禁用全部插件、mcp、hooks、skills，之后可以逐个启用排查。
- **数据**：sqlite完整性检查；从事件日志重建索引；从备份恢复；导出全部数据。
- **设置**：重置设置（先自动备份）；清理缓存。
- **诊断**：把日志和环境信息打成诊断包（已脱敏），可以复制或保存到文件。
- **重新安装**：打开下载页，并说明如何保留数据重装。
- **恢复出厂**：分"保留数据"和"删除数据"两种。

## 6. 数据迁移与回滚

- 每次迁移前自动备份sqlite（用backup api）和设置，保留最近n份。
- 同一大版本内只做加法迁移：加表、加列、加索引。旧版本读新库时忽略不认识的字段，所以回滚应用包不需要回滚数据。
- 破坏性迁移只在大版本升级时做：写新文件（比如`xora.v2.db`），旧文件保留到用户确认为止，回滚时直接用旧文件。
- 事件日志格式升级时写新文件（`events.v2.jsonl`），旧文件不改。
- 清单里的`schema.reads`和`writes`让bootstrap判断回滚是否安全；不安全时，先提示用户再决定。

## 7. 发布、灰度与吊销

- **发布源**：清单和包同时发布到github releases和国内镜像（对象存储+cdn），客户端按网络情况自动选源。
- **签名**：
  - 用ed25519，主私钥离线保存，ci用受限的子密钥签名。
  - 客户端内置公钥，支持轮换。
- **灰度**：按安装id的哈希分桶，按百分比放量；出问题时暂停放量或吊销版本。
- **强制更新**：清单可以设最低版本，只用于严重安全问题。
- **吊销**：清单里列出被吊销的版本，客户端会自动回滚。
- **shell整包更新**：
  - windows：nsis差分更新（blockmap）。
  - linux：appimage。
  - mac：需要开发者证书签名和公证；没有证书时只能提示用户下载新安装包。

## 8. 引擎、预设、扩展的更新

- **引擎**：安装器校验通过后原子切换，保留上一版；acp initialize失败时自动退回。
- **预设**：签名数据包，热加载，失败时退回上一版。
- **扩展**：按市场版本更新，可以锁版本、回滚。
- 以上都能在"设置→更新与版本"里看到历史记录和回滚按钮。

## 9. 演练

每个里程碑都要跑一遍以下场景，并写进自动化测试（见13）：

- 下发一个坏的应用包，验证自动回滚到上一版。
- 让上一版也失败，验证退到内置基线。
- 让基线也失败，验证进入修复模式。
- 吊销一个版本，验证客户端回滚并给出提示。
- 迁移到一半时断电（杀进程），验证可以从备份恢复。
