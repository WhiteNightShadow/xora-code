# Xora Code v1.0.0

1.0是整体重写的版本：不再基于theia和grok build，有了自己的agent引擎、界面和host，也能接codex、claude code等外部agent。在单个线程之外，它把agent组织成一支团队：成员有职责、模型档位、权限和自己的长期记忆，复杂目标交给主管带队，固定流程写成工作流，跑完先给结论。

## 亮点

### 团队成员

- 内置10个成员：主管、规划、计划评审、侦察、编码、测试、文档、修bug、审查、专家；也可以从内置成员改出自己的，用在所有项目，或者只写进当前项目的`.xora/agents/`。
- 每个成员有一份自己记的长期记忆：它干活时用`remember`记下项目事实、你的偏好、踩过的坑，下次干活带上；你能在成员页看、改、清空。
- 直接派活：在选的项目里开一个它的线程，用它的档位模型和权限；在任何线程里写`@名字`，也能把那条消息交给它。
- 例行任务：每天、工作日、每周或任意cron，到点在指定项目里跑一遍，按结论、问题、下一步汇报；无人值守时只用按量计费的模型，不给全权。

### 先给结论的工作流

- yaml写的固定流程：agent步骤、命令、人工关卡、子工作流；看板上一键运行，执行流图实时更新，需要你确认的事就地处理。
- 跑完由旗舰档模型写结论：结论、问题、下一步三段；过程分层收起，点开看每一步；可以对这次运行追问。
- 定时、文件变化、git提交和本机webhook都能触发，可以等模型的低价时段再跑。

### 主管带队的团队运行

- 主管澄清目标、拆任务卡（验收命令、文件归属、预算），另一家的模型评审一次计划，成员在各自的worktree里做，命令验收通过后按依赖整合回项目，最后写交付报告。
- 自主级别L0～L3；概览页能看到管理agent的反馈、每个成员的结论和进度报表；运行中可以给主管或成员发话，结束的运行能接着继续。

### 线程里的日常工作

- 项目和线程，本地或worktree；每一轮的改动单独成卡，带diff，可以撤销整轮或单个文件；分叉、回退、按步压缩。
- 四档权限模式（只读、询问、自动编辑、全权），审批卡片，高风险动作在团队和工作流里永远要人确认。
- 子agent（最多同时4个）、`web_fetch`和`web_search`、终端、预览、skills、斜杠命令、hooks、mcp、插件和市场。

### 模型与引擎

- 预设deepseek、kimi、glm、qwen、minimax、豆包、硅基流动、openai、gemini、openrouter，订阅制的kimi code和glm coding plan，本地的ollama、lm studio、llama.cpp和vllm，也能填任意openai或anthropic兼容的地址。
- 旗舰、标准、经济、快速四档模型链，按已连接的模型自动挑；最多3个备用模型；用量按你的价格表核算，本地模型按0元计。
- 通过acp接codex、claude code、gemini cli、kimi code cli、opencode、qwen code和grok build。

### 更新与恢复

- 界面、host和引擎打成签名的应用包，可以单独热更新；启动前校验签名和全部文件，坏包自动回滚，起不来时进入修复模式。
- 中英双语跟随系统，浅色、深色主题，无边框窗口；新的应用图标。

## 安装

| 系统 | 安装包 |
| --- | --- |
| macos（apple芯片） | `Xora.Code-1.0.0-mac-arm64.dmg`（或`.zip`） |
| macos（intel） | `Xora.Code-1.0.0-mac-x64.dmg`（或`.zip`） |
| windows x64 / arm64 | `Xora.Code-1.0.0-win-x64.exe` / `Xora.Code-1.0.0-win-arm64.exe` |
| linux x64 | `Xora.Code-1.0.0-linux-amd64.deb`或`Xora.Code-1.0.0-linux-x86_64.AppImage` |
| linux arm64 | `Xora.Code-1.0.0-linux-arm64.deb`或`Xora.Code-1.0.0-linux-arm64.AppImage` |

- 安装包没有apple developer id签名和公证，也没有windows authenticode签名。mac第一次打开被拦下时，到“系统设置→隐私与安全性”里点“仍要打开”；windows的smartscreen提示选“仍要运行”。
- 用release里的`SHA256SUMS`核对：`shasum -a 256 -c SHA256SUMS --ignore-missing`。
- linux推荐deb：ubuntu 24.04这类开启了apparmor限制的系统上，deb会装好沙箱需要的配置；AppImage在这些系统上会以`--no-sandbox`启动。

## 从0.2.x升级

- 1.0的数据目录（`xora-code`）和0.2.x（`Xora Code`）分开，两个版本可以并存，装新版不会动旧版的会话和设置。
- 1.0不再内置grok build；想继续用grok，可以在新建线程时选grok build这个外部agent，或者用自定义的openai兼容地址连xai的api。
- 0.2.x的代码保留在`legacy/theia`分支和`legacy/v0.2.10`标签。

## 验证

- mac arm64安装包：更新演练8项全过，真实应用里的界面冒烟全过。
- linux arm64、x64和windows arm64、x64安装包在虚拟机里安装、跑更新演练和界面冒烟，再卸载检查有没有残留。

## 已知限制

- 安装包未签名、未公证（见上）。
- 成员没有单独的花费统计；记忆不按项目分开存；例行任务只能定时触发，没有预算上限。
- 改了成员的设定后，已经开着的对话线程要重启应用才用上新设定（记忆每一轮都是新读的）。
- 应用内的在线更新源还没有发布正式的签名密钥和更新清单，这一版需要手动下载新安装包升级。
