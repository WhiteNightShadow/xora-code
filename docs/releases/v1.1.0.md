# Xora Code v1.1.0

1.1把“找谁干活”收成一个入口：有事跟**总助手**说，它直接回答，或者交给合适的成员、团队、工作流，做完把结果告诉你。团队按常规的组织架构分成小组，审批由主管替你审，只有大批量删除和删库才找你。团队任务提速：拆卡更快，成员交了阶段不用等，卡住时自己收尾出汇报。对话也更顺手：跑着的时候还能接着发（排队），发出的消息能改，`@`就能把消息交给成员。

## 亮点

### 总助手：一个地方说事

- 侧栏最上面的“总助手”是唯一的入口。它能直接回答；需要干活时，交给成员、团队或工作流，对话里有跟进卡片，做完卡片上就是结果。
- 它能管组织：建、改、删成员和小组，用模板一键建出常规开发团队，从GitHub搜skill并装上，注册MCP服务（比如手机上的MCP），再配给要用的成员。
- 侧栏的团队、工作流不再每个项目各一份，各只有一个入口。

### 组织架构和主管代审

- 团队页按小组展示：每组一个组长（主管）和若干成员，成员可以在小组之间移动；内置成员也能删，删了还能恢复。
- “交给这个组”：团队任务由这个组的组长带、组员做。
- 审批默认由主管替你审，它按任务目标判断允许还是拒绝。只有大批量删除（一次删十个以上目标）和删库这类动作才弹给你；审批设置在“设置→权限”里，也可以改回由自己审。

### 团队任务

- 监督闭环：成员分阶段交付，主管看阶段结果、给指导、叫停或升档；主管能替成员审批普通命令。
- 提速：
  - 主管一轮规划最多10次请求，先拆卡，还要调研的放进侦察卡。
  - 有进展的阶段不用等主管评审，成员接着干。
  - 没人盯的运行（L2、L3）卡住时，主管有一轮机会换个办法；不换就合入做完的部分、写出汇报，不再停着等人。
  - 计划定下以后，主管每次被叫醒只看运行状态，不再背整段历史。团队里的对话更早压缩。
  - worktree卡开工时带上项目里没提交的改动，合入时只合入卡自己的改动；在项目目录里同时干活的卡不再互相算错改动。
- 开工前可以给每个成员选模型、思考强度和权限；结束后的汇报只写结果、问题和下一步。
- 运行可以归档、删除；L3能脱手跑（全权成员压到自动编辑，必须设预算）。

### 成员

- 默认用你设的默认模型；也可以给成员单独指定模型，或者在设置里改回“按档位挑模型”。
- 记忆分三份：成员自己的通用笔记、它在每个项目里的笔记、团队在项目里共享的笔记；`recall`能按需查别的项目和别的成员记过的事。
- 对话建人：跟总助手说要什么样的成员，它设计好职责、权限和skill，建到指定小组里。
- 成员可以带MCP服务，干活时优先用这些服务的工具。

### 对话

- 新建对话直接在主区域里写，不再弹框；权限、模型、在本地还是worktree里做，都在输入框下面。
- 跑着的时候还能接着发：消息排在输入框上方，这一轮结束后按顺序发出；可以改、删，或者“现在发”插进这一轮。
- 发出的消息可以编辑：从这条消息起重新开始，可选同时恢复文件。
- `@`的候选里有团队成员，新建对话页和总助手首页也能`@`。
- 对话、团队任务、工作流草稿的标题自动换成内容摘要。
- 设置里的个人提示词可以选任意项目单独写。

### 模型

- MiniMax按官方文档和真实接口核对：M3.1-Flash有低、中、高、最高四档思考，M3可以关思考，M2系列始终思考；思考内容单独显示，带工具调用时原样回传；上下文和输出上限按接口给的写。
- 已经连上的MiniMax不用重新刷新模型列表。

### 图标和细节

- 新图标：白纸上一弯黑线勾出的新月，月牙里一颗四角星，用细线连到节点再到月尖。
- 菜单栏改用单色的模板图标，系统按浅色、深色菜单栏自动着色；16和32像素的小图换成线条更粗的简化版；总助手首页也用应用图标。
- 系统通知显示新的图标和名字；窗口顶部的空白处都能拖动。

## 安装

| 系统 | 安装包 |
| --- | --- |
| macos（apple芯片） | `Xora.Code-1.1.0-mac-arm64.dmg`（或`.zip`） |
| macos（intel） | `Xora.Code-1.1.0-mac-x64.dmg`（或`.zip`） |
| windows x64 / arm64 | `Xora.Code-1.1.0-win-x64.exe` / `Xora.Code-1.1.0-win-arm64.exe` |
| linux x64 | `Xora.Code-1.1.0-linux-amd64.deb`或`Xora.Code-1.1.0-linux-x86_64.AppImage` |
| linux arm64 | `Xora.Code-1.1.0-linux-arm64.deb`或`Xora.Code-1.1.0-linux-arm64.AppImage` |

- 安装包没有apple developer id签名和公证，也没有windows authenticode签名。mac第一次打开被拦下时，到“系统设置→隐私与安全性”里点“仍要打开”；windows的smartscreen提示选“仍要运行”。
- 用release里的`SHA256SUMS`核对：`shasum -a 256 -c SHA256SUMS --ignore-missing`。
- linux推荐deb：ubuntu 24.04这类开启了apparmor限制的系统上，deb会装好沙箱需要的配置；AppImage在这些系统上会以`--no-sandbox`启动。

## 从1.0.0升级

- 直接装新版，数据目录不变，对话、成员、记忆和设置都保留。
- 成员的旧记忆会自动按项目分开：带项目标记的笔记归到那个项目，其余的留作通用笔记。
- 审批默认改成主管代审。想自己审，到“设置→权限→审批”里改回“我自己”。
- macOS的Dock可能还缓存着旧图标，重启Dock（或者重新登录）后就换成新的。

## 已知限制

- 安装包未签名、未公证（见上）。
- 排队的消息只能在用户自己开的对话里用；团队、工作流和子agent的线程由宿主开轮。
- 编辑发出的消息时，图片附件没有保存，不会重发。
- 应用内的在线更新源还没有发布正式的签名密钥和更新清单，这一版需要手动下载新安装包升级。
