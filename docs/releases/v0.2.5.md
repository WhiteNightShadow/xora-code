# Xora Code v0.2.5

> **Stable / Production**：`v0.2.5` 是 Xora Code 当前稳定生产版本。该版本由同一份已提交源码分别在 macOS、Windows 与 Linux 原生环境构建，统一内嵌并校验 Grok Build `0.2.102`。

Xora Code 是一款开源的 Grok 桌面应用与 Grok Build GUI 客户端。它将项目树、代码编辑器、终端、流式 Agent 对话、计划、工具活动、Diff 审阅、权限控制、Skills 和 MCP 管理放进同一个跨平台桌面工作区。

## 本版重点

### 模型、思考等级与 Provider

- **Grok 4.6 / xhigh**：思考等级来自 ACP 模型能力，不按模型名称硬编码；Grok 4.6 可展示并使用 `low`、`medium`、`high`、`xhigh`，旧模型或未声明能力的模型自动隐藏或回退。
- **全局记忆**：模型与思考等级按 Provider / 模型安全保存，新会话、其他项目、其他窗口和应用重启都会继承最近选择。
- **动态更新**：在设置中修改模型 ID、协议、上下文窗口或推理配置后，Agent 选择器立即更新，不再要求重启 IDE。
- **安全切换**：从自定义 API 切换到 Grok 订阅，或在旧历史中切换模型时，会先完成当前 Provider 的会话重绑；单会话模型状态不再覆盖完整运行时模型目录。
- **兼容服务**：继续支持 OpenAI Responses、OpenAI Chat Completions 与 Anthropic Messages，可接入 OpenAI API、DeepSeek 等兼容端点及 Claude API。网页订阅不能替代 API 凭据，工具、图片、联网与推理能力以服务端和 Grok Build 的实际声明为准。

### Agent 交互与历史

- **紧凑输入区**：模型与思考等级合并为一个选择入口；审批方式保持可见；常规 / 持续完成、附件和上下文收纳为紧凑工具组，并移除冗余 Enter 提示。
- **图片上下文**：支持粘贴或选择 PNG、JPEG、WebP，草稿标签可预览；Runtime 未声明原生 ACP 图片能力时，图片会经过校验后保存为项目附件并向 Agent 提供相对路径。
- **完整历史分页**：切换会话默认只绘制最新 180 条记录；继续向上阅读时，Electron 使用稳定 JSONL 字节游标加载更早页面并保持滚动位置，可越过旧版 5000 条 / 16 MiB 读取边界。
- **Windows 历史游标**：NTFS 的 64 位文件身份使用无损 BigInt 读取与十进制字符串编码，不再因超过 JavaScript 安全整数范围而拒绝加载更早记录；旧版安全整数游标继续兼容，文件被替换时仍会安全拒绝。
- **思考与长任务**：思考过程保持实时流式、小字展示并在单次思考完成后自动收起；持续完成继续使用原生 `/goal` 和“模型结束 / Xora 验收”双状态，不会自动把普通任务变成长任务。
- **会话隔离**：多会话并行、同会话消息排队、文字与图片草稿、任务模式和重试状态继续彼此隔离。

### 可靠性与跨平台体验

- **Windows 外壳**：Activity Bar 隐藏改为产品级不变量；旧布局、目录切换与用户插件恢复后仍保留 Explorer，不再出现多余图标栏。
- **链接与文件导航**：长 OSS 签名 URL 不再被误判为本地文件；中文路径、多根工作区与外部路径继续按当前权限安全定位。
- **认证与历史重绑**：登录成功后会主动恢复当前历史会话；模型列表加载与会话 hydration 使用单飞同步，避免“新建会话后才恢复”的过渡错误。
- **固定运行时**：三端安装包均使用 Grok Build `0.2.102`，启动时执行版本、平台、摘要和 ACP 初始化校验；运行时自动更新仍由 Xora Code 统一关闭和管理。

## 签名与安装提示

- **macOS**：当前使用 ad-hoc 签名，没有 Apple Developer ID，也没有 notarization，Gatekeeper 可能拦截首次启动。
- **Windows**：当前没有 Authenticode 产品签名，SmartScreen 可能显示未知发布者。
- **Linux**：提供 SHA-256 校验和，尚未提供 GPG detached signature。
- **自动更新**：签名更新信任锚尚未配置，因此本版本不会声称已启用正式自动更新；应用与官网更新失败不会影响现有本地功能。

本项目由社区独立维护，不是 xAI 官方客户端，与 xAI 不存在隶属、赞助或背书关系。“Grok”与“Grok Build”仅用于准确描述上游集成与互操作能力。
