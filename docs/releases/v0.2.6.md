# Xora Code v0.2.6

> **Stable / Production**：`v0.2.6` 是 Xora Code 的 Windows 输入与会话可靠性补丁版本。它由同一份已提交源码分别在 macOS、Windows 与 Linux 原生环境构建，继续内嵌并校验 Grok Build `0.2.102`。

Xora Code 是一款开源的 Grok 桌面应用与 Grok Build GUI 客户端。它将项目树、代码编辑器、终端、流式 Agent 对话、计划、工具活动、Diff 审阅、权限控制、Skills 和 MCP 管理放进同一个跨平台桌面工作区。

## 本版修复

### Windows 富文本粘贴

- 严格识别 Windows CF_HTML 剪贴板封包，不再把 `Version`、`StartHTML`、`StartFragment` 等传输元数据粘贴进 Agent 输入框。
- 优先使用 Fragment 标记，缺失时按 UTF-8 字节偏移提取内容，正确处理中文、Emoji、HTML 实体与换行。
- 普通文本仍使用系统原生粘贴；图片和 CF_HTML 同时存在时，图片附件继续保留。

### 会话一致性与安全发送

- 只暂时保护刚创建且尚未被 Electron 权威快照确认的会话；确认后的会话若被删除，界面会同步清理，不再保留可发送的“幽灵会话”。
- 对缺失会话使用稳定的 `SESSION_NOT_FOUND` 状态。仅当后端确认 ACP 尚未接收任务时，Xora Code 才会最多创建一次替代会话并继续；用户事件已经产生或执行状态不明确时绝不自动重放。
- Prompt 在保存附件、写入用户消息和发起 ACP 请求前，通过跨进程锁原子认领会话；其他窗口不能在任务执行期间删除同一会话。
- 会话删除、Provider 失效、历史恢复和持续完成入口统一遵守任务所有权，避免并发发送、半条历史或孤立附件。

### Windows 会话索引

- NTFS 设备号、64 位文件 ID、大小和高精度时间戳使用 BigInt 无损签名，避免超出 JavaScript 安全整数后误用陈旧索引缓存。
- 写事务持锁后强制重新读取权威磁盘状态，降低多个窗口并发更新时的 ABA 风险。
- Windows 原子替换期间的瞬时 `ENOENT` 会有界重试；崩溃遗留临时文件不会把首次启动永久阻断，也不会把已有会话索引误判为空。

## 兼容性

- Provider、模型选择、Grok Home、Skills/MCP 配置和本地会话历史保持兼容，不执行数据格式迁移。
- Grok Build sidecar 继续固定为 `0.2.102`；本版修复位于 Xora Code 的 Electron 会话边界和 Agent 输入层。
- 旧会话如果已不存在于本地索引，原始草稿会保留；Xora Code 不会因恢复失败自动重放历史任务。
- Windows 升级前请完全退出所有 `v0.2.5` 窗口并确认没有残留的 Xora Code 进程，再运行 `v0.2.6` 安装包；旧版进程不会理解新版任务所有权字段，不应与新版并行操作同一会话索引。

## 验证范围

- CF_HTML Fragment 标记、UTF-8 字节偏移、中文/Emoji、实体、普通文本、图片混合粘贴和光标选区回归。
- 本地创建与快照乱序、权威删除、迟到事件、跨窗口删除/发送、Prompt 原子认领和不重放门禁。
- NTFS 超大文件 ID、索引缓存失效、原子替换瞬时缺失和崩溃临时文件恢复测试。
- TypeScript 全仓构建、Agent / Fake ACP / 产品外壳测试，以及三端安装包的版本、架构、sidecar、插件、notices、SBOM 和摘要校验。

## 签名与安装提示

- **macOS**：当前使用 ad-hoc 签名，没有 Apple Developer ID，也没有 notarization，Gatekeeper 可能拦截首次启动。
- **Windows**：当前没有 Authenticode 产品签名，SmartScreen 可能显示未知发布者。
- **Linux**：提供 SHA-256 校验和，尚未提供 GPG detached signature。
- **自动更新**：签名更新信任锚尚未配置，因此本版本不会声称已启用正式自动更新；应用与官网更新失败不会影响现有本地功能。

本项目由社区独立维护，不是 xAI 官方客户端，与 xAI 不存在隶属、赞助或背书关系。“Grok”与“Grok Build”仅用于准确描述上游集成与互操作能力。
