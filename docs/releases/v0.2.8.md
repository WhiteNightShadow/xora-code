# Xora Code v0.2.8

本版修复自定义 API 切换后的思考等级选择，以及 Skills/MCP 配置保留与共享问题。先在 macOS arm64 构建、覆盖安装并验证。

## 切换后立即选择思考等级

- 激活 Agent 面板时保留用户正在操作的下拉框焦点，避免输入框抢焦点而关闭选项。
- 模型服务切换时清理旧选择器状态；旧服务的异步模型加载和保存结果不能覆盖新服务。
- 修复新会话草稿的模型目录加载，切换 A → B → A 也无需再切到“活动”页面触发刷新。

## 用户级配置共享，项目级配置叠加

- Skills 和 MCP 继续来自共享 Grok Home 与当前项目配置；切换 API 只改变模型路由和认证上下文。
- 技能列表保留原生用户、项目、配置路径及兼容来源，不再只显示单一来源；保留实际禁用状态。
- API 专用运行目录同步共享原生 Skills 目录及 `[skills].paths`；保留已有非空目录中的用户内容。
- MCP 沿用共享用户级与项目级注册，通过 ACP 注入当前会话，仍受项目信任和服务器凭据绑定约束。
- MCP 状态列表兼容原生 Grok 的嵌套 ACP 响应，避免已连接并发现工具后仍显示“未加载”。
- 独立认证目录用于防止订阅登录状态被带到自定义 API；清理旧登录状态失败时会阻止启动。

## 保存模型服务时保留其他配置

模型配置编辑按 TOML 语法识别具体表和赋值，只更新属于 Xora 的模型条目。Skills、MCP、注释和其他用户设置即使进入旧版托管标记区，也应保留。写入前比较无关配置的解析结果，发现意外变化就停止写入；继续保留原配置备份。

Windows 字面量路径、多行数组、引号表名、内联表及包含伪标记的多行字符串均有回归覆盖。无效的共享配置会明确报错，避免以空的技能配置覆盖已有运行目录。

## 对用户反馈的判断

“文件仍在，但配置或发现结果丢失”的判断有代码依据。旧实现会整段删除托管标记之间的内容，确实可能误删其中的 `[skills]` 与 `[mcp_servers]`；技能列表的来源过滤还会隐藏本来可用的技能。

普通模型更新会保留标记区之外的配置，因此仅凭反馈不能断定每次新增 API 都清空整个 `~/.grok/config.toml`。本轮未读取反馈中 Windows 原机的配置与备份，具体时间线和路径仍以原机文件为准。

项目配置位于项目目录下的 `.grok/config.toml`，例如 `D:\项目\V3\.grok\config.toml`。它是项目级覆盖；用户级 Skills/MCP 仍应保存在共享 Grok Home。已经丢失的配置需依据原备份恢复，本版不会猜测并覆盖用户当前设置。

现有 `[paths].extra_skill_dirs` 会保留并同步，但固定 Grok Build `0.2.102` 的原生 `inspect` 在共享基线和 API 目录中均未发现仅由该字段配置的测试技能。相同目录通过 `[skills].paths` 已验证可发现；该兼容字段的运行时可用性本轮未确认。

Grok Build 保持固定为 `0.2.102`；应用与工作区包版本更新为 `0.2.8`。
