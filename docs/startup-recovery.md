# 启动与异常恢复

连接异常时，先查看 Agent 面板的状态和错误提示。连接失败后可以点击右上角“重新连接 Agent”，无需重新创建会话。重连只恢复连接，草稿和失败消息仍保留；需要重发的任务由用户明确重试。

| 场景 | 应用处理 | 恢复操作 |
| --- | --- | --- |
| 临时连接失败、重复初始化 | 合并同一启动请求，保留后台预热的有界重试；停止操作可取消正在等待的 ACP 初始化 | 自动恢复失败后点击“重新连接 Agent” |
| 旧进程尚未退出 | 清理进程和通信流；未确认退出时保留进程句柄，阻止新进程抢占 | 稍后重新连接；仍失败时完全退出应用再打开 |
| 钥匙串授权或凭据解密卡住 | 在独立 Electron 进程处理系统加解密，等待上限 15 秒；失败或中断标记跨重启保留，后台不重复尝试 | 检查系统授权窗口、解锁钥匙串后点击“重新连接 Agent”，或在“账户与模型设置”中重新保存密钥 |
| 网络盘离线、工作区文件异常 | 本地工作区恢复准备最多等待 8 秒，失败后进入空窗口；保留历史记录并暂停重复恢复 | 连接网络盘或修复工作区文件后，从“文件 → 打开最近的工作区”重新打开，或打开其他文件夹 |

凭据只通过独立进程的 IPC 通道传递，不进入命令行参数、日志或明文文件。恢复标记不包含密钥；删除已保存密钥不需要再次解密。启动只准备当前模型服务和工作区所需凭据，列出模型服务和收集脱敏信息不会解密其他模型服务的凭据。

本地目录、挂载盘和 UNC 路径使用上述工作区恢复流程；非 `file:` 的远程工作区仍沿用 Theia 的远程连接处理。系统凭据授权仍由操作系统决定，重试不能绕过授权或修复已损坏的加密内容。
